클론업 설계 정리

2026년 8월 9일 화면 시안 8종 미결 2건

지금까지 만든 화면과 그 근거, 그리고 아직 정하지 못한 것을 한자리에 모았습니다. 화면 시안은 모두 실제 코드를 읽고 그 동작에 맞춰 그렸습니다. 코드가 바뀌면 이 문서의 해당 항목도 함께 검토해야 합니다.

1. 이 앱이 지키는 원칙

작업하면서 반복해서 적용한 판단 기준입니다. 새 화면을 만들 때도 이 네 가지를 먼저 확인하면 됩니다.

  1. 메뉴는 git 명령이 아니라 목적으로 나눕니다. 이용자는 revert 와 reset 을 구분하지 못합니다. 대신 무엇을 얻고 무엇을 잃는지로 나눕니다.
  2. 겁을 주지 않고 겁낼 곳을 특정합니다. 대부분의 동작은 잃는 것이 없습니다. 되돌릴 수 없는 것은 공개로 올리기와 기록 삭제 둘뿐이며, 이 둘에만 경고색을 씁니다.
  3. 안내는 한 번으로 끝내지 않습니다. 첫 실행 안내는 지도 역할만 하고, 위험한 동작은 실행 직전에 다시 확인합니다.
  4. 한계를 숨기지 않습니다. 비밀 파일 점검이 파일 안쪽을 보지 못한다는 사실은 화면에도 약관에도 적었습니다.

3. 되돌리기 기능의 설계

가장 많이 고민한 부분입니다. 초보자가 말하는 되돌리기 하나에 위험도가 다른 작업 여럿이 섞여 있어, 무엇을 넣지 않을지가 설계의 대부분이었습니다.

1차에 넣은 것
이 시점 파일 보기 · 이 시점으로 되돌리기(기록을 남기는 방식) · 되돌리기 전 백업 브랜치 자동 생성 · 되돌린 뒤 자동 푸시
넣지 않기로 한 것
기록까지 지우고 되돌리기(강제 푸시). 남의 사본을 깨뜨릴 수 있는 유일한 동작이라 초보자용 앱에서 제외했습니다.

이 결정에 맞춰 첫 실행 안내도 고쳤습니다. 4단계는 두 방식을 비교하는 대신 되돌리기가 커밋을 쌓는 과정을 그림으로 보여주고, 대가표에서도 제외한 기능의 행을 없앴습니다. 앱에 없는 기능을 초보자에게 가르칠 이유가 없습니다.

되돌리기를 기록을 남기는 방식으로 정한 것이 이 기능 전체를 단순하게 만들었습니다. 아무것도 잃지 않으므로 목록에서 골라 바로 실행해도 안전하고, 되돌리기를 또 되돌릴 수 있습니다. 실행하면 목록 맨 위에 새 커밋이 쌓이는 것을 화면이 직접 보여줍니다.

다만 자동 푸시를 선택했기 때문에, 확인 창에서 공개 저장소라면 곧바로 공개된다는 점을 경고색으로 표시합니다. 되돌리기 자체는 안전해도 그 결과가 공개되는 것은 별개의 문제입니다.

4. 초보자 안내를 넣는 방식

안내를 한곳에 몰아넣지 않고 네 층으로 나눕니다. 층마다 목적이 다릅니다.

  1. 탭 아래 한 줄 안내. 각 탭이 무엇을 하는지 한 문장. 항상 보입니다.
  2. 입력란 옆 도움말. 오해가 실제로 발생하는 지점에만 답니다. 저장소 주소, 저장소 이름, 공개 범위, .git 없는 폴더.
  3. 실행 전 확인. 비밀 파일 후보가 있을 때, 그리고 첫 커밋 전 공개될 이메일을 알릴 때.
  4. 로그 창의 해석 한 줄. 이미 코드가 한국어 오류 메시지를 반환하므로, 그 문장 뒤에 다음 행동만 덧붙입니다.

2번을 항상 보이게 할지 접을지, 그리고 첫 실행 안내를 어디까지 짧게 줄일지는 아직 정하지 않았습니다.

5. 코드를 읽다 발견한 것

약관을 쓰기 위해 동작을 확인하는 과정에서 나온 사항입니다. 화면 설계에도 영향을 줍니다.

  1. 앱에 로그아웃이 없었습니다. 토큰 삭제는 재인증 경로에서만 일어납니다. 설정 창 계정 항목에 로그아웃 버튼을 넣어 두었습니다.
  2. 권한 범위가 넓습니다. repo 는 비공개 저장소까지 포함합니다. 승인 화면 앞에 평이한 말로 설명하는 안내가 필요합니다.
  3. 이메일 보호가 절반만 적용됩니다. Git 설정이 없을 때만 noreply 주소를 씁니다. 이미 설정해 둔 사람은 실제 이메일이 공개되므로, 첫 게시 전에 알려주는 편이 안전합니다.
  4. 비밀 파일 점검은 파일 이름만 봅니다. 안쪽에 적힌 비밀번호는 찾지 못합니다. 이 한계를 화면과 약관 양쪽에 적었습니다.
