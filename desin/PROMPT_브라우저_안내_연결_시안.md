## 복사해서 쓸 프롬프트

```text
당신은 CloneUp(한국어 초보용 GitHub 도우미 데스크톱 앱)의 UI/UX 디자이너입니다.
목표는 「브라우저에서 로그인」으로 GitHub 개인 액세스 토큰(키, classic PAT)을 만드는
전체 사용자 여정을 빠짐없이 담은 디자인 시안(화면 플로우 + 각 화면 레이아웃)을 만드는 것입니다.

# 제품·톤
- 대상: Git을 잘 모르는 한국어 초보. 영문 GitHub 화면을 그대로 쓰되, CloneUp 안내는 쉬운 한국어.
- 톤: 짧고 친절. 한 화면에 하나만 묻기. 기술 용어(PAT, OAuth, scope)는 최소화하고 「키」「권한(repo)」정도로.
- 비주얼 시스템(라이트 기준, 다크 변형도 제안):
  - 배경 #fbfaf8 / 바 #f2efe9 / 테두리 #c9c5bd·#ddd8d0
  - 본문 #2f2b24 / 보조 #4a453b / 흐림 #6d675c
  - Primary(청록) #1f6f5c, hover #185b4b, 버튼 글자 흰색
  - 경고 앰버 패널 #fbf6ee / 테두리 #c4a94e
  - 폰트: IBM Plex Sans KR + 주소/키는 IBM Plex Mono
  - 모서리 8–10px, 카드형, 그림자 과하지 않게
- 기존 시안 계열: CloneUp Window / GitHub 연결 / 연결 흐름 과 톤을 맞출 것.
- Path B 안내 창은 OS 브라우저 위에 뜨는 작은 플로팅 패널 (불투명도 약 50%, 기본 z-order는 다른 창 뒤·바탕화면에 가깝게, 클릭하면 앞으로, 접기/펼치기 가능).

# 절대 규칙 (시안에 반드시 반영)
1. 연결 창은 한 번에 하나만. 「브라우저에서 로그인」을 고르면 방식 선택 마법사는 닫히고, 작은 「브라우저 안내」창만 남는다.
2. CloneUp은 브라우저 안의 Google/패스키/비밀번호를 가로채지 않는다. 안내는 옆에서 상태만 보여 준다.
3. 기본 키 종류 = classic Personal access token, 권한은 repo만 미리 체크. (세분 키는 이 시안의 주경로가 아님)
4. Note(이름) = CloneUp-YYYYMMDD-HHMMSS 형태. 중복 시 새 이름으로 다시 연다.
5. 키 문자열(ghp_… / github_pat_…)은 화면에 평문으로 길게 노출하지 말 것(마스킹·비밀번호 칸).
6. Device Flow(장치 코드)는 이 시안에 넣지 말 것.
7. 「했어요」로 브라우저와 맞추지 않는다. 진행은 주소/화면 감지·클립보드·키 인식이 기준.

# 여정 전체 (시간순 — 화면마다 시안 1장 이상)

## A. CloneUp에서 시작
A1. 메인 창 상태줄 「GitHub: 연결」(또는 설정 → 계정 「다시 로그인」/「새 키로 다시 연결」).
A2. 방식 선택 팝업
    - 제목: 첫 연결이면 「로그인 방식을 고르세요」 / 재연결이면 「새 키로 다시 연결」
    - 본문: 어디서 로그인할지 고르기. 창은 하나만. Google·패스키가 편하면 브라우저 가능. 키 목록·세분 키는 설정.
    - 버튼: [앱 안에서 로그인] Primary · [브라우저에서 로그인] Secondary · [취소] Ghost
    - ※ 이 시안의 주인공은 「브라우저에서 로그인」 이후(Path B).

## B. Path B 전환
B1. 방식 선택 창이 닫힌다.
B2. OS 기본 브라우저가 GitHub 로그인(https://github.com/login)을 연다. (자동)
B3. 동시에 CloneUp 「브라우저 안내」작은 창이 화면 좌상단 근처에 뜬다.
    - 창 제목: CloneUp — 브라우저 안내
    - 불투명도 ~50%, 기본적으로 다른 앱(브라우저) 뒤에 가려질 수 있음. 사용자가 안내를 클릭하면 앞으로.
    - 헤더: 제목 + [접기 ▴]/[펼치기 ▾]
    - 펼친 상태 구성:
      · 제목 / 짧은 안내 문장
      · 주소: (브라우저 주소창을 읽은 값, 모노스페이스)
      · 검증: (지금 단계를 한 줄로)
      · 할 일 체크리스트 4칸 (아래 C)
      · 상황별 보조 버튼(평소 숨김): GitHub 로그인 다시 열기 / 키 만들기 페이지 열기 / 마지막으로 열었던 페이지로 돌아가기
      · 키 입력칸(비밀번호형) + 붙여넣기 + 보기/숨기기
      · 상태 한 줄
      · [취소] · [연결](키 인식 전 비활성)
    - 접힌 상태: 제목 + 한 줄 상태 + 키 칸 + 취소/연결만. 창 높이 축소.

## C. 체크리스트 (할 일) — 상태 기호
각 행 기호:
- ○ 아직 / → 지금 진행 중 / ✓ 완료 / ! 경고(막힘·오류)
고정 4단계 문구:
1. GitHub 로그인 (비밀번호·패스키·Apple·Google)
2. 로그인 완료 확인
3. Generate new token 으로 키 만들기
4. 키 복사하기

## D. 브라우저 안에서 일어나는 일 (시안에 브라우저 목업 + 안내 창 병치)

### D0. 시작 — GitHub Sign in
- 브라우저: github.com/login (Sign in to GitHub)
- 안내 창 제목 예: 브라우저에서 이어서 하세요
- 안내: 비밀번호·패스키·Apple·Google 중 편한 방법으로 로그인한 뒤 키를 만들어 주세요.
- 체크: 1번 → 진행 중

### D1a. 비밀번호 로그인
- 브라우저: username/email + password
- 안내: GitHub 로그인 화면 — 진행 중

### D1b. 패스키 (Windows OS 시트)
- 브라우저 위 OS 패스키/QR 창
- 안내 제목: 패스키 확인 중
- 안내: Windows 패스키 창입니다. 휴대폰 QR 또는 이 기기에서 확인하세요.
- 체크: 1번 진행 중 (완료로 세지 않음)

### D1c. Apple로 로그인
- 브라우저: appleid.apple.com 등
- 안내 제목: Apple로 로그인 중 → 끝나면 GitHub으로 돌아옴

### D1d. Google로 로그인 (정상)
- 브라우저: accounts.google.com
- 안내 제목: Google로 로그인 중

### D1e. Google 막힘 (중요 예외 — 성공으로 치지 말 것)
- 브라우저: insecure browser / 거절 메시지
- 안내 제목: Google 로그인이 막혔어요
- 안내: 다른 방법(패스키·Apple·비밀번호) 가능. 「GitHub 로그인 다시 열기」버튼 노출.
- 체크 1번에 ! Google 막힘. 진행도 올리지 않음.

### D1f. 2단계 인증(OTP)
- 브라우저: /sessions/two-factor 등
- 안내: 인증 코드 입력 중으로 표현 (체크 1번 유지 또는 진행 중)

### D2. 로그인 완료
- 브라우저: github.com 홈(로그인된 상태)
- 안내 제목: 로그인됐어요. 키를 만들어요
- 안내: 키 만들기 페이지로 안내합니다. Generate token을 누르세요.
- 검증: 로그인 완료 — 키 만들기로 이동
- 체크: 1·2 ✓ , 3 →
- 동작: CloneUp이 classic 키 만들기 URL을 자동으로 열 수 있음
  https://github.com/settings/tokens/new?scopes=repo&description=CloneUp-YYYYMMDD-HHMMSS

### D2-out. 로그아웃/미로그인 감지 (초기화)
- /logout 이거나 Sign in·Sign up UI가 보이면
- 안내: 로그아웃되었어요 / 로그인이 필요해요 → 진행 상태 리셋, 체크 초기화

### D3. classic 키 만들기 폼
- 브라우저: settings/tokens/new
  · Note: CloneUp-시각 (미리 채워짐)
  · scopes: repo 체크됨 (CloneUp이 필요한 권한)
  · Expiration: 사용자가 고름(7/30/60/90/없음 등) — 시안에 「만료일 고르기」힌트
  · 하단 Generate token (또는 Generate new token)
- 안내 제목: 키를 만들어 주세요
- 안내: repo가 체크돼 있어요. Generate token을 누르세요.
- 체크: 3번 →

### D3-err. Note 이름 중복
- 브라우저 플래시: Note has already been taken
- 안내 제목: Note 이름이 이미 있어요
- 안내: Note를 바꾸거나 「다른 이름으로 열기」(키 만들기 페이지 열기)로 새 CloneUp-시각 URL
- 체크 3번에 ! Note 이름 중복

### D4. 키 발급 직후 (한 번만 보이는 화면)
- 브라우저: “Make sure to copy your personal access token now…” + 토큰 문자열
- 안내 제목: 키를 복사해 주세요
- 안내: 복사되거나 화면에 보이면 자동으로 연결합니다.
- 체크: 4번 → 또는 ✓
- CloneUp 동작:
  · 클립보드에 ghp_/github_pat_… 감지 → 키 칸에 자동 입력 → 「연결」활성 → 자동 연결 시도
  · 또는 화면에서 키가 보이면(접근성) 동일
  · 안 되면 사용자가 복사→붙여넣기→연결

### D5. 흐름을 벗어남 (강제 아님)
- 브라우저가 GitHub 로그인/토큰 계열이 아닌 다른 사이트
- 안내 제목: 지금은 GitHub 작업 화면이 아니에요
- 안내: 원하시면 마지막 페이지로 돌아가도 됩니다. (자동 이동 금지)
- 버튼: 「마지막으로 열었던 페이지로 돌아가기」

### D6. 연결 성공 → CloneUp으로 복귀
- 안내 창 닫힘
- CloneUp 메인이 앞으로, 연결됨 상태(점·계정 표시)
- 토큰은 OS keyring에만 저장. .env / .git/config에 안 넣음.
- (선택) 설정→안전에 마스터 비밀번호 보호가 켜져 있으면 암호문으로 저장 — 이 시안에서는 한 줄 주석만.

## E. 시안에 넣을 화면 목록 (최소 세트)
1. 방식 선택 (새 키로 다시 연결 / 첫 연결)
2. 브라우저 안내 — 펼침 · 로그인 대기
3. 브라우저 안내 — 접힘(컴팩트)
4. 병치: GitHub Sign in + 안내
5. 병치: 패스키 OS 창 + 안내
6. 병치: Google 막힘 + 안내(재열기 버튼)
7. 병치: 로그인 완료 홈 + 안내(키 만들기로)
8. 병치: tokens/new 폼(Note·repo·Generate) + 안내
9. 병치: Note 중복 오류 + 안내
10. 병치: 토큰 발급(복사 배너) + 안내(자동 인식)
11. 흐름 이탈 + 돌아가기 버튼
12. 연결 완료 후 CloneUp 메인 상태줄
13. (보너스) 다크모드 방식 선택 + 안내 창

# 산출물 형식
1. 전체 플로우 다이어그램(위 단계 A→D6) 1장
2. 각 E화면 와이어/하이파이 목업(라이트 우선, 다크는 보너스)
3. 컴포넌트 스펙: 안내 창 폭 ~380–440px, 접힘 높이 축소, Primary/Secondary/Ghost 버튼, 체크리스트 행, 경고 배너
4. 마이크로카피 표: 화면별 제목 / 본문 / 검증 한 줄 / 버튼 라벨 (위에 적힌 한국어 문장 우선 사용, 임의로 영어화하지 말 것)
5. 하지 말 것 목록을 시안 주석으로 명시

# 시작
먼저 플로우 다이어그램과 화면 목록(E)을 확정한 뒤, 화면 2·4·8·10을 우선 하이파이로 그려 주세요.
```
