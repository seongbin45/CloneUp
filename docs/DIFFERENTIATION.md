# CloneUp — 무엇을 더 잘할지 (GitHub Desktop · Bitbucket 대비)

기준일: 2026-08. 제품 방향 메모. 기능 전체 복제가 목표가 아니다.

## 한 줄 포지션

> **GitHub Desktop이 아니어도 되는 사람**을 위한 앱이 아니라,  
> **GitHub Desktop이 부담스러운 초보 한국어 사용자**가  
> 「로컬 폴더 → GitHub 첫 업로드 / 받기 / 동기화」만 **안전하게** 끝내게 한다.

Bitbucket(웹)과 Sourcetree(데스크톱)는 **팀·Atlassian 생태계·고급 Git** 쪽이다.  
CloneUp은 **개인·GitHub·첫 경험**에만 초점을 둔다.

---

## 왜 Git인가 (이 앱이 감추지 않는 이유)

Git CLI를 버튼으로만 감싸는 것이 목표가 아니다. 초심자가 **왜 이 도구를 쓰는지**를  
탭·상태 문구·온보딩에 남기는 것이 CloneUp의 설계 기준이다.

| Git 개념 | 초심자 언어 | CloneUp에서의 자리 |
|----------|-------------|-------------------|
| 커밋 | 지금 폴더 상태를 **돌아올 수 있는 점**으로 남김 | 만들고 올리기 / 동기화 메시지, 커밋 내역 |
| 원격(GitHub) | PC 밖 기록(push로 맞춤; 자동 클라우드 아님) | 만들고 올리기 · 받기 · 동기화 연결 |
| push / pull | 내 기록 ↔ 원격 기록을 **맞춤** | 올리고 보내기 · 받아오기, 상태의 “보낼/받을 커밋 N개” |
| 충돌 | 같은 줄을 양쪽에서 고쳐 **자동 합치기 실패** | 상태 안내 · **충돌 취소** (합치기 시도 포기) |
| 되돌리기 | 예전 점으로 내용을 되살림 (보통 **새 커밋**) | 커밋 내역 — 충돌 취소와 **다른 동작** |

**의식적으로 안 하는 것:** 브랜치 그래프, rebase, 충돌 파일 자동 병합 UI.  
이유는 “풀 Git 클라이언트”가 되면 초보 첫 성공과 반대 방향이기 때문이다.  
대신 **실수 비용이 큰 일**(공개 올리기, 비밀 파일, 이력 변경)을 먼저 드러내고 막는다.

## 비교 표

| 축 | GitHub Desktop | Bitbucket / Sourcetree | **CloneUp (우리가 지는 길)** |
|----|----------------|------------------------|------------------------------|
| 대상 | 일상 Git + GitHub 전 구간 | 팀 코드 호스팅·Jira 연계·고급 클라이언트 | **첫 3동작**만 (만들고 올리기 / 받기 / 동기화) |
| 언어·카피 | 영어 중심 제품 카피 | 영어·엔터프라이즈 | **한국어 평이한 말** (팁 카드 G1–G2, 실패 시 「다음:」 G4) |
| 안전 | 일반 diff/커밋 UI | 정책·권한은 조직 쪽 | **올리기 직전 비밀파일·PII 확인 (G3)** |
| Git 설치 | 앱에 Git 내장 | 별도/복잡 | **Git 없으면 설치 안내·winget (부트스트랩)** |
| 인증 신뢰 | **GitHub 공식** OAuth | Atlassian 계정 마찰 | **PAT(키)만 기본** — 공개 Device Flow client_id 남용 차단 |
| 범위 욕심 | 브랜치·히스토리·PR·충돌… | rebase·stash·멀티호스트… | **일부러 안 함** (풀 Git GUI 경쟁 금지) |

## 상대가 강한 점 (우리가 따라가지 않을 것)

1. **GitHub Desktop** — 브랜치·커밋 히스토리·PR·diff의 완성도.  
   → CloneUp은 “풀 Git 클라이언트”가 되면 지고, 제품도 무거워진다.
2. **Bitbucket** — 이슈·파이프라인·조직 권한.  
   → 호스팅 플랫폼이 아니다. GitHub 전용 도우미로 남는다.
3. **Sourcetree** — 시각적 그래프·고급 명령.  
   → 초보 첫 업로드와 반대 방향이다.

## CloneUp이 더 나을 수 있는 가치 (우선순위)

### V1. **신뢰 (Trust)** — 공개 Device Flow 공격 면 제거
- 공개 `client_id` + Device Flow: **악성 프로그램이 같은 ID로 폴링**하면 승인 화면이 같아 토큰을 가로챌 수 있음.
- **대응 (적용)**
  - **기본 인증 = PAT(키)만.** Device Flow 자동 시작 없음.
  - `CLONEUP_ALLOW_DEVICE_FLOW=1` 일 때만 개발용 Device Flow.
  - 토큰은 **절대 `.git/config`에 안 씀**.
  - **선택:** 설정 → 안전 **마스터 비밀번호 보호** — keyring 암호문 + DPAPI DEK.  
    일상 사용은 비번 없이, 마스터 비번은 디스크에 두지 않음.  
    상세: [MASTER_PASSWORD_VAULT.md](MASTER_PASSWORD_VAULT.md).

### V2. **안전 업로드 (Safety)** — 이미 있고, 더 키울 축
- Desktop은 파일을 올릴지 말지 사용자가 diff로 고른다. 초보는 `.env`를 몰라서 같이 올린다.
- CloneUp **G3** (비밀 파일명 + 전화/이메일 패턴)이 차별점.
- 다음: 성공 후에도 “공개면 링크가 인터넷에 노출됩니다” 한 번 더, 오탐 설명 보강.

### V3. **안내형 실패 (Guided fail)** — 이미 있고 유지
- G4 「다음: …」. Desktop은 오류 영문·일반적.
- 한국어 다음 행동 한 줄 유지·확장.

### V4. **제로 세팅 경로** — Git 부트스트랩
- Desktop은 Git 내장. 우리는 시스템 Git + 설치 안내.
- “설치 못 하겠다”를 줄이는 쪽이 가치 (DG2/DG3 유지).

### V5. **첫 성공 의식** (이후)
- 올리고 난 뒤: 브라우저에서 열기 · 다음에 동기화 탭 쓰기 · 공개/비공개 의미.
- Desktop tutorial repo 대신 **방금 내 폴더** 기준.

---

## 하지 않을 것 (의식적)

- 브랜치 UI, merge conflict 해결기, stash, rebase
- Bitbucket / GitLab 멀티 호스트 (당분간)
- 서버형 동기화 서비스, 계정 백엔드 (토큰은 로컬 keyring만)

## 성공 기준 (차별화가 먹혔는지)

1. “이 앱 OAuth를 믿기 싫은데” → **PAT로 같은 기능**이 된다.
2. 초보가 `.env`를 모르고 올리려다 **막히거나 확인**을 받는다 (Desktop 대비).
3. 실패 로그에 **다음 행동**이 한국어로 보인다.
4. 기능 목록 길이로 Desktop과 비교하지 않는다.
