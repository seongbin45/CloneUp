# Git을 초심자에게 와닿게 설명하려면

CloneUp 제품·온보딩·설정 「용어 안내」·문서 작성 원칙입니다.

**고정**

- 화면 버튼·탭 이름은 **교체하지 않는다** (만들고 올리기, 받기, 동기화, 충돌 취소, 커밋 내역…).  
- 목표는 “지금 이해되는 비유”만이 아니라 **6개월 뒤에도 모순이 적은 모델**이다.  
- 정확성과 친절함이 충돌하면 **정확성**을 택하고, 대신 **문장을 짧게** 한다 (아래 정량).

---

## 0. 설계 원리 셋

| # | 원리 | 내용 |
|---|------|------|
| 1 | **통과 시험** | 비유를 미리 막기만 하지 말고, **유형별 필수 시험**에 대입. 실패하면 폐기 |
| 2 | **유효 범위 선언** | 비유는 어딘가에서 약해진다. 약해지는 지점은 **문서에 미리 적는다** |
| 3 | **자리·관계는 비유, 동작은 사실 짝** | 동사 비유 허용. 단 **직후 정식 용어 사실 문장 1개** 필수 |

### 필수 폐기 규칙 (예외 명문화)

- **필수(A) 실패는 “범위 밖” 선언으로 우회할 수 없다.**  
- 우회하고 싶으면 그 항목을 **B(확장)로 강등하는 문서 개정을 먼저 커밋**한 뒤에만 가능하다.  
- 필수 실패를 범위 밖으로 빼서 비유를 살리는 것은 **규칙 위반**이다.

### “금지 목록만”의 함정

제약을 부정 나열로만 촘촘히 하면 모델이 **비유를 통째로 포기**하거나,  
“깨지는 비유인지 스스로 알면 애초에 안 썼다”는 **검증 불가 제약**만 남는다.  
그래서 **시험 항목을 키우는 쪽**이 맞고, 관측된 실패 비유 목록은 **짧게 고정**한다.

## 1. 비유 유형별 필수 시험

비유를 쓸 때 **유형을 고른 뒤**, 그 유형의 A만 전부 통과해야 유지한다.  
짧은 카드는 해당 유형 A만.

### 유형 P — 자리 비유 (예: 원고 제출)

| ID | 필수 시험 |
|----|-----------|
| P1 | 수정 파일 5개 중 **2개만** 골라 커밋할 수 있는가 |
| P2 | **인터넷 없이** 커밋 10개 쌓고 나중에 한 번에 push가 설명되는가 |
| P3 | **untracked** 파일이 있을 수 있는가 |
| P4 | 남이 먼저 push해 내 push가 **거절**되는 상황이 설명되는가 |

### 유형 G — 그래프 비유 (예: 이름표/스티커)

| ID | 필수 시험 |
|----|-----------|
| G1 | **브랜치 2개**가 동시에 **같은 커밋**을 가리킬 수 있는가 |
| G2 | **reset ≠ revert** 가 구분되는가 |
| G3 | **merge**가 갈래를 없애는 게 아니라 **새 커밋 하나**를 만드는가 |
| G4 | 과거를 지우기보다 **새 기록을 덧붙이는** 방식이 설명되는가 |

### 확장 B (유형 공통 · 실패 시 유효 범위 축소 선언만 허용)

부분 커밋 이름, merge 세부, conflict, .gitignore, clone=역사, 등 —  
**필수 A를 대체하지 않는다.**

### 금지 대상 — 명사가 아니라 동사 서술

Git 저장 모델에 가까운 **명사 비유**(스냅샷, 사진 한 장) 자체는 허용할 수 있다.  
실제로 깨지는 것은 아래 **동사 서술**이다.

| 금지 동사 서술 (사용자 대면) | 왜 |
|------------------------------|-----|
| 과거로 **돌아간다** / **불러온다** / 시간을 **되돌린다** | reset·revert·checkout을 한 동작으로 뭉갠다 |
| **자동으로** 맞춰진다 / 드라이브처럼 **알아서** 동기화된다 | push/pull 누름이 사라진다 |
| 통째로 **이사**한다 / **복사본 보관**만 한다 | 커밋 선별·이력이 안 보인다 |

**고유명·실제 기능 예외 (금지 어휘에 걸려도 통과)**  
제품이 실제로 하는 일·버튼·파일·명령 이름은 비유가 아니다.

- 예: 「되돌리기 전에 **백업 브랜치**를 만듭니다」— 정확, 유지  
- 예: `git commit`, `git push`, 탭 이름 「만들고 올리기」

### 관측된 실패 비유 묶음 (짧게 · 더 늘리지 말 것)

통째 복사 보관 / 자동 클라우드 동기화 /  
타임머신·과거로 감(동사) / 브랜치=폴더 복사 / USB·단순 파일 전송  

「세이브포인트」「사진」**명사만**으로 금지하지 않는다.  
「찍어 둔 만큼 **돌아간다**」처럼 동사가 붙으면 금지.

새 실패가 나오면 이 목록이 아니라 **시험 항목**에 추가한다.

### 사용자 대면 텍스트

> 금지 비유는 사용자 화면에서 **부정형으로도 언급하지 않는다.**  
> ✗ “자동 클라우드가 아닙니다” · “타임머신이 아닙니다”  
> ✓ “받아오기·올리고 보내기를 누를 때만 맞춰집니다.”

집필 규칙·레포 경로·“6개월 뒤 폐기” 같은 **작성자용 말**은 사용자 카드에 넣지 않는다.

## 2. 동사 비유 규칙 (현실화)

- 동사 비유 **허용** (“봉인해 꽂는다”, “출판사로 보낸다”).  
- 단 **바로 다음 문장**에 정식 용어 사실 1개:  
  `git commit`은 … / `git push`는 …  
- 사실 문장 없이 동사 비유만 있는 문단은 폐기.

## 3. 문장 길이 (정량)

| 대상 | 기준 |
|------|------|
| 한 줄 요약 | **45자 이내**, 주어–서술어 1쌍, **이중 부정 금지**, “~않으면 ~없습니다” 금지 |

## 4. 주 비유: 원고 제출 (유형 P)

| 자리 | 비유 | 정식 | 클론업 |
|------|------|------|--------|
| 1 | 책상 위 원고 | working tree | 작업 폴더 |
| 2 | 봉투에 넣을 장 | staging / `git add` | (UI 세분 없을 수 있음) |
| 3 | 봉인·내 서고 | `git commit` | **커밋** |
| 4 | 출판사 | remote / `git push` | **GitHub**, **올리고 보내기** |

**유효 범위:** 네 자리와 남기기·보내기 관계.  
**유형 G 질문은 이 비유로 풀지 않는다** — 이름표 비유 또는 사실 서술.

### 유형 P 대입 결과 (유지 근거)

| ID | 결과 |
|----|------|
| P1 | 통과 — 봉투에 넣을 장만 고름 = staging 선별 |
| P2 | 통과 — 서고에 여러 봉인 후 출판사로 일괄 발송 |
| P3 | 통과 — 책상 위 장 중 아직 봉투에 안 넣은 것 = untracked/미선별 |
| P4 | 통과 — 출판사 서가 상태가 바뀌어 내 발송이 거절될 수 있음 |

### 그래프 비유: 이름표 (유형 G)

| ID | 대입 |
|----|------|
| G1 | 통과 — 스티커 두 장이 같은 페이지를 가리킬 수 있음 |
| G2 | 통과 — reset≈이름표를 다른 페이지로 옮김(주의: 세부 옵션 많음) / revert≈“이전으로 되돌린 내용”을 **새 페이지로 덧붙임**. 제품 되돌리기는 후자 쪽 |
| G3 | 통과 — 두 이름표가 가리키던 줄기를 이어 **새 페이지(merge commit) 한 장**을 씀 |
| G4 | 통과 — 기본 안전 경로에서 과거 페이지를 찢지 않고 새 장을 덧붙임 |

**유효 범위:** 어디를 가리키는가·새 장이 생기는가.  
checkout 다의성·reflog·force push는 사실로만, 짧게 또는 범위 밖.

## 5. 출력 구조 (장문 문서)

1. 성공 경로 먼저 (add→commit→push 또는 만들고 올리기)  
2. 직후 네 자리  
3. 가능하면 status 영어 문자열 전/후  
4. 에러 제목 = 원문 (authentication failed, non-fast-forward, …)  
5. 오해 부르는 이름: add / origin / checkout 한 번 고지  

클론업: **보여주면서 해주는 도구** (상태·확인·로그). 대신만 하면 용어 안내와 충돌.

## 6. 서술 금지

- 의인화: “Git이 알아서”  
- 빈 안심: “걱정 마세요”, “그냥 외우세요”  
- 사고 종료: “일단 이렇게만” (이유 예고 없이)  
- 사용자 카드에 **조건문으로 제품 동작을 모호하게** (“~이면”) — 동작 확정 후 단정

## 7. 클론업 맵 (현재 UI 존재)

| 말 | 역할 |
|----|------|
| 만들고 올리기 | 첫 commit·remote·push 흐름 |
| 받기 | clone |
| 동기화 | pull/push 등 맞춤 |
| 커밋 내역 | 목록; 설정 시 되돌리기=**새 커밋 덧붙임** (히스토리 재작성 없음) |
| 충돌 취소 | merge/rebase --abort |

## 8. 짧은 답 · A만

자리 비유 → P1–P4. 그래프 비유 → G1–G4.  
검수 시 해당 유형 필수에 **직접 대입**. 형식만 채운 “전부 통과”는 의심.

## 9. 기계 검사 (`scripts/lint_git_terms.py`)

**의미 타당성(비유가 시험에 통과하는지)은 스크립트가 판정하지 않는다.**  
사람이 `METAPHORS` 레지스트리에 판정·근거를 적고, 도구는 **선언 일관성**과 텍스트 규칙을 본다.

```powershell
.\.venv\Scripts\python.exe scripts\lint_git_terms.py app\ui\git_terms_ko.py
```

| 도구가 함 | 도구가 안 함 |
|-----------|----------------|
| 금지 어휘·부정형 시드, 메타 누수, 길이, 병기, UI 단어 | 비유가 “진짜로” 맞는 의미 판단 |
| 필수 실패인데 사용 중(MT006), 미검증(MT004) | 의도적 완곡 우회(“보관본” 등) 전부 차단 |

ERROR가 있으면 커밋·CI 실패. CI: `.github/workflows/ci.yml`.
