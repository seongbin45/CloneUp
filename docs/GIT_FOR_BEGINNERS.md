# Git을 초심자에게 와닿게 설명하려면

CloneUp 제품·온보딩·설정 「용어 안내」의 **설명 원칙**입니다.

**규칙**

- 화면 버튼·탭 이름(**만들고 올리기**, **받기**, **동기화**, **충돌 취소**, **커밋 내역** 등)은 **교체하지 않는다**.  
- 비유는 **설명에만** 쓰고, 가능하면 **정식 용어(commit, push, remote…)** 를 병기한다.  
- 목표는 “지금 이해되는 말”만이 아니라 **6개월 뒤에도 안 깨지는 모델**이다.

---

## 0. 목표를 다시 잡기

「더 쉬운 비유」만 찾다 보면 초심자용 Git 문서가 망한다.  
비유는 **보조**이고, 먼저 전달할 것은 **자리(where)** 와 **이름표(branch/HEAD)** 모델이다.

사람은 **성공한 다음 이해**한다.  
입장료로 다이어그램을 받지 말고, **첫 성공 직후**에 “왜 여러 단계였나”를 설명한다.

클론업 GUI를 만들 때 정해야 할 것:

| 종류 | 결과 |
|------|------|
| **대신 해주는 도구** | 편하지만 모델을 영영 못 배울 수 있음 → README·용어 안내와 충돌 |
| **보여주면서 해주는 도구** | 상태·다음에 할 일·(가능하면) 기록 변화를 화면에 노출 |

클론업은 후자를 지향한다: 상태 문구, 확인창, 로그, 용어 안내로 **지금 어느 자리인지**를 말함.

---

## 1. 깨지는 비유 (쓰지 말 것 / 쓸 때 한계를 못 박을 것)

| 비유 | 어디서 깨지나 |
|------|----------------|
| **백업** | “통째로 복사” 오해. **커밋 안 한 파일은 안 올라감**을 설명 못 함. “저장했는데 GitHub에 없죠?” 유발. |
| **구글 드라이브** | 드라이브는 **자동** 동기화, Git은 **전부 명시적**. 이 비유를 믿은 사람은 반드시 실패. |
| **게임 세이브포인트** | 선형. **브랜치**가 나오는 순간 무너짐. staging을 못 담음. |
| **타임머신** | “과거로 돌아간다” → `reset` / `revert` / `checkout` 구분을 망침. Git은 과거를 **가리키는 이름표**를 다루는 쪽에 가깝다. |

클론업 카피에서 “백업·세이브”를 쓸 경우:  
**한계 한 줄**을 붙이거나, **원고 제출** 비유로 바꾼다.

---

## 2. 실제로 전달할 두 문장

초심자 혼란의 대부분은 여기로 압축된다.

### (1) 파일이 있을 수 있는 자리가 넷이다

| 자리 | 쉬운 말 | 정식에 가까운 말 |
|------|---------|------------------|
| 1 | 책상 위 원고 (마음대로 고침) | working tree / 작업 폴더 |
| 2 | 봉투에 넣을 것만 고름 | staging / index (`git add`) |
| 3 | 봉투 봉해 **내 서고**에 꽂음 | local repository / **커밋** (`git commit`) |
| 4 | **출판사**로 보냄 | remote / **GitHub** (`git push`) |

초심자는 자리가 **둘**(내 컴퓨터, GitHub)이라고 믿는다.  
에러 메시지의 상당수는: **“지금 이게 어느 자리인지 착각”**.

클론업은 UI에서 staging을 세세히 보여 주지 않을 수 있다.  
그래도 설명에서는:

> 만들고 올리기·동기화는 보통 폴더 내용을 한 흐름으로 커밋까지 가져가지만,  
> Git 자체에는 위 네 자리가 있다. **커밋 전까지는 GitHub에 안 간다.**

### (2) 브랜치는 복사본이 아니라 이름표다

- 커밋들은 **사슬**로 이어진다.  
- **브랜치** = 사슬의 한 지점에 붙인 **스티커**.  
- **HEAD** = “지금 내가 보고 있는 곳” 표시.

“브랜치 = 폴더 통째 복사”로 가르치면 merge에서 무너진다.  
클론업이 브랜치 UI를 앞에 두지 않는 이유: 초심자는 먼저 **네 자리**를 익혀야 한다.  
이름표 모델은 용어 안내·고급 단계에서 심는다.

---

## 3. 안 깨지는 비유: 원고 제출

| 단계 | 비유 | 정식 / 클론업 |
|------|------|----------------|
| 고침 | 책상 위 원고 | 작업 폴더 |
| 고르기 | 봉투에 넣을 장 고르기 | `git add` (선별; 이름은 “추가”로 오해 유발) |
| 남기기 | 봉인·라벨·**내 서고** | `git commit` / 클론업의 커밋 메시지 |
| 보내기 | **출판사**로 발송 | `git push` / **올리고 보내기** · 만들고 올리기 |

“왜 여러 단계냐?” → 이 표로 답이 된다.  
부분 커밋·로컬만 커밋·원격은 나중 — 같은 그림이 이어진다.

---

## 4. 비유보다 효과 큰 것: 반응(status)

초심자가 무서워하는 이유 중 하나는 **반응이 없어서**다.  
`git add` 후 화면이 조용하면 공포가 된다.

이상적 문서: 단계마다 **status 전/후**를 붙인다.  
Untracked → staged → clean 으로 **같은 파일의 자리 이름**이 바뀌는 걸 보면, 네 자리가 생긴다.

클론업에서의 대응:

- 동기화 **상태** 문구 (보낼/받을 커밋, 충돌, 맞춤)  
- 올리기 전 **확인** (G3)  
- 아래 로그 · 「다음:」  
- 설정 **용어 안내**

→ “대신만 해주는” 것이 아니라 **지금 어디인지 말해주는** 쪽.

---

## 5. 해가 되는 친절 두 가지

### (1) 용어를 마음대로 재명명

비유만 쓰고 `commit`/`push`/`remote`를 지우면 **에러 검색이 불가능**해진다.  
초심자 문서의 목적 중 하나: **스스로 검색할 수 있게**.

- 비유 = 설명용  
- **정식 용어 병기** (커밋 = commit, 올리고 보내기 ≈ push)

### (2) 명령 이름이 멀쩡한 척

| 이름 | 오해 | 한 줄 |
|------|------|--------|
| `add` | 추가 | 사실상 **선별** (staging에 올림) |
| `origin` | 원본 | 그냥 **기본 별명**인 경우가 많음 |
| `checkout` | 한 가지 일 | 맥락에 따라 **다른 일**을 함 |

“이름이 이상해서 헷갈리는 거지, 당신 탓이 아니다” — 자책을 줄인다.

---

## 6. 목차: 성공 경로만이 아니라 실패 화면

초심자는 수 분 안에 실패한다.  
인증, `non-fast-forward`, `src refspec main does not match any`, main/master, 편집기 탈출…

**와닿는다 = 방금 본 화면이 문서에 있다.**  
에러 **원문을 소제목**으로 두는 편이, 비유 다듬기보다 검색 유입에 효율적이다.  
→ 제품 쪽: 실패 메시지에 **다음 행동** + 가능하면 원문 힌트 (이미 G4 「다음:」 축).

---

## 7. 순서 (절충)

1. **짧은 성공** (만들고 올리기 / 동기화로 한 바퀴)  
2. 직후 **“왜 여러 단계였나”** → 네 자리 + 원고 비유  
3. 충돌·되돌리기는 **다른 버튼**으로 구분  
4. 브랜치 이름표 모델은 그다음  

모델 다이어그램을 입장료로 받지 말 것.

---

## 8. 클론업 맵 (제품 단어 유지)

| 감각 / 모델 | 클론업에서 |
|-------------|------------|
| 책상 위 원고 | 로컬 폴더 |
| 내 서고에 봉인 | **커밋** (메시지) |
| 출판사 | **GitHub** |
| 처음 출판 | **만들고 올리기** |
| 서고 가져오기 | **받기** |
| 맞추기 | **동기화** · **올리고 보내기** · **받아오기** |
| 겹침 | **충돌** |
| 합치기 포기 | **충돌 취소** (시도 직전; 커밋 내역 되돌리기와 다름) |
| 점 목록 | **커밋 내역** |

## 9. 앱 안 위치

| 장소 | 역할 |
|------|------|
| 시작 안내 (도움말) | 폴더 둘 · 커밋 · 루프 · 대가 · 안전 |
| 설정 → **용어 안내** | `app/ui/git_terms_ko.py` — 화면 말 + 쉬운 풀어쓰기 + 정식 병기 |
| 동기화 상태 | 어느 쪽이 앞섰는지 / 충돌 이유 |
| 탭 팁 | 각 탭의 왜 (비유는 한계  cognizant) |

용어 카드 추가 시: **UI 라벨 재명명 금지**, 깨지는 비유 금지, 가능하면 commit/push 병기.
