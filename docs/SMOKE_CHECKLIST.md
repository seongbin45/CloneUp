# GUI 스모크 체크리스트 (push 직전 · 10–15분)

pytest는 GUI·실제 GitHub 경로를 보증하지 않습니다. **본인 PC에서** 실행.

## 0. 준비

- [ ] 최신 로컬 `main`으로 앱 기동: `.\.venv\Scripts\python.exe main.py`
- [ ] 테스트용 빈 폴더 하나 (만들고 올리기용)
- [ ] (선택) 그 폴더에 `.env` 파일 하나 두기 — G3 경로 강제

## 1. 로그인 경로 (가장 먼저 · 깨질 확률 높음)

### 1-A. 세분 키만 (의도적 한계 확인)

1. 로그아웃된 상태에서 「GitHub: 연결」
2. 가능하면 **세분 키 + 해당 저장소만 + Contents 읽기/쓰기** 로 발급 시도  
   - 막히는 지점 기록: 저장소 목록 비어 있음 / 권한 항목 없음 / 기타
3. 그 키로 연결 후 **만들고 올리기**  
   - 실패 시: 대화상자·로그 **원문** + 「다음: …」 문구 그대로 메모
4. 결과: □ 발급 단계에서 막힘 / □ 연결은 됨·만들기는 실패 / □ 성공(예외)

### 1-B. classic `repo` (대표 경로)

1. Tokens (classic) · **repo** 한 줄 · 만료 설정 · 키 복사
2. 「GitHub: 연결」 붙여넣기
3. **만들고 올리기** 1회 (비공개 권장)  
   - □ 성공 · 저장소 URL: ________
4. 1-A 실패 + 1-B 성공이면: 세분 1순위 안내는 **조건부 문구 유지/수정** 근거가 됨 (이미 classic 1순위로 교정됨 — 회귀 확인)

## 2. G3 비밀 파일 (경로가 돌았는지)

1. 올리기 폴더에 `.env` 가 있는지 확인 (없으면 만들기)
2. 만들고 올리기 또는 동기화 올리고 보내기  
   - □ 막힘 대화상자가 뜸  
   - □ “검사/올리지 않음”으로 이해 가능  
   - □ (있으면) staging 설명 문장이 과장/틀린지 메모 → push 후 세 자리 작업 때 정리

## 3. 자리 문구 (낮은 우선 · 한 번만 훑기)

- [ ] 온보딩 1단계: **두 곳** (staging 입장료 없음)
- [ ] 화면에 staging을 **필수로** 찾지 않아도 됨

## 4. push (스모크 결과와 무관하게)

```powershell
cd CloneUp
git status -sb
git push origin main
```

- 통과 → 그대로 push  
- 실패 → **실패 내용 이슈/메모 후 그래도 push**, 그다음 수정  

main push ≠ Setup 릴리스. 사용자는 Setup.exe만 받음.

## 5. push 후 백로그 (지금 하지 말 것)

1. 자리 모델 **세 자리 + staging 각주** 번복 여부 + 용어 “오해”→단계적 확장  
2. 5명 무안내 로그인 테스트  
3. Setup 릴리스
