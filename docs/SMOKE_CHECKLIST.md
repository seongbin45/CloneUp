# GUI 스모크 체크리스트 (push 직전)

pytest · lint · “종료 코드 0”은 **이 표를 채우지 않습니다.**  
아래 네 칸은 **본인 PC에서 `main.py` + 실제 GitHub 키**로 돌린 수기만 유효합니다.  
에이전트가 칸을 대신 채웠다면 무효로 보고 다시 하십시오.

**결과와 무관하게 push 하십시오.** main ≠ Setup 릴리스.  
실패 시: 아래 메모에 붙이고 `git push origin main` 한 뒤 수정.

```powershell
cd CloneUp
.\.venv\Scripts\python.exe main.py
# …스모크…
git push origin main
```

## 경로 표 (이게 전부)

| # | 토큰 | 탭 | 기대 | 결과 (수기) |
|---|------|-----|------|-------------|
| **1** | **classic `repo`** | **만들고 올리기** | **성공해야 함** (주 경로) | □ 성공 URL: ____ / □ 실패: |
| **2** | **세분** + **해당 저장소** + **Contents R/W** | **동기화** (이미 있는 저장소 폴더) | **성공해야 함** (보조 경로) | □ 성공 / □ 실패: |
| **3** | **세분** (Contents 등, 새 이름 없음) | **만들고 올리기** | **실패 예상** | 에러 원문: ____ 「다음:」: ____ |
| **4** | classic `repo` (1과 동일 키 OK) | **만들고 올리기** + 폴더에 **실제 `.env` 파일** | G3 차단이 **실제로** 돌아감 | □ 차단 대화상자 / □ 안 뜸 |

### #3 진짜 검사 항목

실패 자체만이 아니라, 초심자가 이해할 수 있는가:

- [ ] 「다음:」에 **새 저장소 → classic 키** 안내가 있는가  
- [ ] 원문만 (`Resource not accessible by personal access token` 등)이면 **실패 기록** (문구 수정 백로그)

### #4

- [ ] `.env`를 **실제로 만들어 둔 상태**에서 돌렸는가 (없으면 G3 미실행 “통과” 금지)

## push 후 백로그 (지금 하지 말 것)

1. 자리 모델 **세 자리 + staging 각주** 번복 + 용어 “둘=오해” → 단계적 확장  
2. G3/팁의 “.env = staging” 부정확 매핑 제거  
3. 탭별 토큰 안내 (로그인 다이얼로그에서 종류 고르지 않기)  
4. 5명 무안내 로그인 (임계: **3명 이하 통과 시 게이트 B 재개방** 정당)  
5. Setup 릴리스
