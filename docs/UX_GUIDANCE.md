# CloneUp — 초보자 안내 4층 (단계 적용)

목표: 실패 케이스(`FAILURE_CASES.md`)와 약관에만 있던 설명을 **화면 안**에서 평이한 말로 보여 준다.

## 결정 (합의)

> **문서 규칙:** 결정 표·감사 추적용 본문에는 **git SHA를 적지 않는다.**  
> 로컬 커밋 해시는 리베이스/스쿼시로 바뀌며 origin에 없는 `fatal: bad object` 링크가 된다.  
> 인용은 `날짜 + 커밋 제목` 또는 `decision/*` 태그. (2026-08 교차검증에서 재확인)

| 질문 | 선택 | 근거 (결론 반복 금지) |
|------|------|----------------------|
| **힌트 형태** | **탭당 접는 팁 카드 1장** | 공간↓. 접힘=한 줄, 펼침=G1+G2 |
| **필드 아래 상시 회색 글** | 쓰지 않음 (clone 루트 안내는 기존 배너 유지) | 창 길이 부담 |
| **첫 실행 안내** | **적용** 7단계 전체화면 모달 | 코드 구현됨. 예전 「3단계 보류」와 다름. 번복 사유 **미기록**이었음 → 마찰 증가를 인정한 채 유지 중. 단계 수·1단계 배치는 아래 「자리 모델 배치」로 따로 관리 |
| **자리 모델 (개념)** | **네 자리 유지** (작업 폴더 · staging · 커밋 · GitHub) | 비밀 파일 제외를 설명하려면 폴더와 GitHub 사이에 자리가 하나 더 필요하고, 로컬 커밋과 원격의 차이는 동기화 탭에 이미 숫자로 노출되어 있으므로 네 자리. 단 staging은 UI에 없으므로 온보딩 1단계가 아니라 `.env` 설명 지점에서 도입 |
| **자리 모델 (배치)** | 1단계=**두 곳** · staging=**.env/비밀 파일 안내** · 전체 그림=**설정 → 용어 안내** | 첫 성공 전에 화면에 없는 자리를 입장료로 요구하지 않음 |
| **로그인 방식 (게이트 B)** | **PAT 기본** (Device Flow = env opt-in) · 연결 마법사 **1순위 = classic `repo`** | **실질 근거는 하나뿐:** 1인 프로젝트라 공개 client_id Device의 사칭 신고·대응 여력이 없다. 「사용자 제어(만료·범위)」이점은 신규 저장소 생성이 classic `repo`(전 저장소 R/W)를 요구하므로 **실제로는 얻지 못한다.** (2026-08, 커밋 제목: *classic repo is default for 만들고 올리기; fine-grained secondary* — SHA는 문서에 적지 않음: 리베이스 시 끊김.) |

### S2 사실 확인 (코드 근거, 2026-08-12)

| Q | 답 | 근거 |
|---|-----|------|
| Q1 staging UI 노출? | **아니오** | 파일별 선택 UI 없음. `publish.py` 내부 `git add` |
| Q2 add→commit→push? | **한 번에** (메시지·안전 검사 제외) | `publish_folder_to_new_repo` / ensure 경로: safety → add → commit → push |
| Q3 비밀 제외 시점? | **commit/push 직전 안전 검사** | `run_safety_checks` · G3. **staging 미선택이 아님** — 검사 관문 |
| Q4 커밋 메시지 입력? | **예** | `editCommitMessage` (만들고 올리기·동기화) |

**자리 모델 후속 (push 후 · 번복 후보):** Q3 때문에 “.env → staging 도입” 매핑은 부정확. 관측 가능한 자리는 폴더 / 로컬 커밋 / GitHub 셋. staging은 UI 없음 → **세 자리 + staging 각주** 검토. 용어 카드 “둘=오해”와 온보딩 1단계 “두 곳” 충돌도 함께.

### S4 단계 수 (대략, 초심자 관점)

| 경로 | 단계 수 | 막힐 수 있는 지점 (예) |
|------|---------|------------------------|
| **PAT (세분, 기존 저장소 동기화)** | **약 9** | Fine-grained → 저장소 선택 → Contents → 복사·붙여넣기. **만들고 올리기(새 저장소)와 맞지 않을 수 있음** |
| **PAT (classic `repo`, 주 경로)** | **약 8** | repo 체크 · 전 저장소 권한 · 클립보드. 만들고 올리기 = `POST /user/repos` 에 맞춤 |
| **Device Flow** (opt-in) | **약 4** | 코드 표시 → 브라우저 → 입력 → 승인. 비밀 문자열 없음 |

**단계 수 기준의 한계 (반드시 남김):**  
“Device 단계 ≤ PAT/2 이면 안 2”만 보면 Device(~4) vs classic(~8)은 **2배·안 2 충족**. 그런데 결론이 PAT인 이유는 단계 축이 아니라 **개발자 사칭 대응 여력** 축이다. 6개월 뒤 “숫자만 보면 Device인데 왜 PAT?”가 반복되지 않도록 이 문장을 유지한다.

**5명 무안내 로그인 테스트:** 근거가 “대응 여력” 하나로 줄었으므로, 재개방 임계를 **5명 중 2명 이하 → 3명 이하 통과**로 올려도 정당하다. 미측정.

### 미채택 대안 (기록)

| 대안 | 요약 | 미채택 이유 |
|------|------|-------------|
| 저장소 생성은 GitHub 웹, 앱은 push만 | 세분 + 해당 저장소 + Contents로 충분해질 수 있음 | “첫 업로드를 앱 안에서 끝낸다” 차별점 훼손. PAT 발급 벽이 5명 테스트로 확인되면 재검토 |
| 로그인 다이얼로그에서 classic/세분 고르기 | 토큰 종류를 초심자에게 물음 | 만들고 올리기/동기화 **탭이 이미 목적 선언** → push 후: 탭 진입 시 필요한 토큰만 안내하는 쪽이 낫다 (미구현) |

- **만들고 올리기** / **동기화 → 올리고 보내기** 직전 `QMessageBox`
- **층 구분 (2026-08 스모크 재확인):** 새 폴더에 쓰는 기본 `.gitignore`가 `.env`·`*.pem` 등을 **커밋 후보에서 제외**하면 G3 파일명 스캔은 그 파일에 **돌지 않음** (업로드도 안 됨 — 보호는 gitignore 층). G3 **「올릴 수 없음」** UI는 발행 목록에 남은 이름(`credentials` 등, 정규식 `_SECRET_NAME_RE`)일 때 뜸.

- 파일 **내용** 개인정보 패턴 (전화·이메일)
  - 확인만 (차단 아님) + **오탐 가능** 명시 (예시 번호 등)

- 항상: **커밋에 남을 작성자 주소**
  - 체크 **「커밋에 내 이메일 숨기기 (권장)」** (기본 켜짐)

  - 공개/비공개는 “누가 보느냐”만 바꿈 (주소 자체를 만들지 않음)

메인 창은 다이얼로그 두 개와 달리 **처음 열릴 때 자동으로 전체화면 진입하지 않습니다** — 일반 데스크톱 앱 기대와 다르면 오히려 방해가 되므로, F11을 눌러야만 토글됩니다. 안내 문구(`Esc 닫기 · F11 …`)도 다이얼로그의 인-윈도우 타이틀 바에만 있고 메인 창에는 넣지 않았습니다 — OS 타이틀 바만 있고 넣을 자리가 마땅치 않기 때문.
