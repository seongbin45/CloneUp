# CloneUp — 초보자 안내 4층 (단계 적용)

목표: 실패 케이스(`FAILURE_CASES.md`)와 약관에만 있던 설명을 **화면 안**에서 평이한 말로 보여 준다.

## 결정 (합의)

| 질문 | 선택 | 근거 (결론 반복 금지) |
|------|------|----------------------|
| **힌트 형태** | **탭당 접는 팁 카드 1장** | 공간↓. 접힘=한 줄, 펼침=G1+G2 |
| **필드 아래 상시 회색 글** | 쓰지 않음 (clone 루트 안내는 기존 배너 유지) | 창 길이 부담 |
| **첫 실행 안내** | **적용** 7단계 전체화면 모달 | 코드 구현됨. 예전 「3단계 보류」와 다름. 번복 사유 **미기록**이었음 → 마찰 증가를 인정한 채 유지 중. 단계 수·1단계 배치는 아래 「자리 모델 배치」로 따로 관리 |
| **자리 모델 (개념)** | **네 자리 유지** (작업 폴더 · staging · 커밋 · GitHub) | 비밀 파일 제외를 설명하려면 폴더와 GitHub 사이에 자리가 하나 더 필요하고, 로컬 커밋과 원격의 차이는 동기화 탭에 이미 숫자로 노출되어 있으므로 네 자리. 단 staging은 UI에 없으므로 온보딩 1단계가 아니라 `.env` 설명 지점에서 도입 |
| **자리 모델 (배치)** | 1단계=**두 곳** · staging=**.env/비밀 파일 안내** · 전체 그림=**설정 → 용어 안내** | 첫 성공 전에 화면에 없는 자리를 입장료로 요구하지 않음 |
| **로그인 방식** | **PAT 기본** (Device Flow = env opt-in) | **1인 프로젝트**라 공개 client_id Device의 사칭·신고 대응 여력이 부족해 기본에서 제외 (업계가 client_id를 쓰는 것과 별개로 대응 여력 차이). 사용자 단계만 보면 Device(~4)가 PAT 세분(~9)의 절반 이하라 단계 기준만으로는 안 2이나, **운영 리스크 축**을 넣어 PAT 유지. 세분 키는 좁은 권한에 유리하지만 「만들고 올리기」= `POST /user/repos` 이라 **없는 저장소·Contents만**으로는 막힐 수 있음 → **1순위 안내는 classic `repo`**, 세분은 기존 저장소 동기화용 보조 |

### S2 사실 확인 (코드 근거, 2026-08-12)

| Q | 답 | 근거 |
|---|-----|------|
| Q1 staging UI 노출? | **아니오** | 파일별 선택 UI 없음. `publish.py` 내부 `git add` |
| Q2 add→commit→push? | **한 번에** (메시지·안전 검사 제외) | `publish_folder_to_new_repo` / ensure 경로: safety → add → commit → push |
| Q3 비밀 제외 시점? | **commit/push 직전 안전 검사** | `run_safety_checks` · G3 대화상자. 작업 폴더에는 남을 수 있음 |
| Q4 커밋 메시지 입력? | **예** | `editCommitMessage` (만들고 올리기·동기화) |

### S4 단계 수 (대략, 초심자 관점)

| 경로 | 단계 수 | 막힐 수 있는 지점 (예) |
|------|---------|------------------------|
| **PAT (세분 권장)** | **약 9** | GitHub 로그인 → Developer settings 찾기 → Fine-grained → 저장소 고르기 → Contents 권한 → 만료 → Generate → **문자열 복사** → 앱 붙여넣기 |
| **PAT (classic)** | **약 8** | 동일 계열 + repo 체크 (저장소 선택은 없음, 대신 과잉 권한) |
| **Device Flow** (opt-in) | **약 4** | 앱에서 코드 표시 → 브라우저 열기 → 코드 입력 → 승인 |

절반 기준(안 2 권고 조건: Device 단계 ≤ PAT/2)을 숫자만 보면 **Device ≈ 4, PAT ≈ 8–9** 로 안 2 쪽이다.  
그럼에도 PAT 유지 근거는 **단계 수가 아니라** 공개 client_id 사칭 리스크 회피(위 표).  
**비용(몇 명이 로그인 실패)은 아직 미측정** — 주변 5명 무안내 로그인 테스트 권장.

### G3 (적용 · 카피 강화)

- **만들고 올리기** / **동기화 → 올리고 보내기** 직전 `QMessageBox`
- 비밀 **파일명** 후보 (`.env` 등)
  - 체크 안 함 → **차단** + 다음 행동 1)·2) + 오탐(`.env.example`) 안내
  - 체크 함 → 확인 후 진행 + 「내용 스스로 확인」 문구
- 파일 **내용** 개인정보 패턴 (전화·이메일)
  - 확인만 (차단 아님) + **오탐 가능** 명시 (예시 번호 등)
- 공개/비공개 위험을 **평이한 말**로 구분
- 항상: **커밋에 남을 작성자 주소**
  - 체크 **「커밋에 내 이메일 숨기기 (권장)」** (기본 켜짐)
    → 이번 커밋만 GitHub **가림 주소** (PC Git 설정 안 바꿈)
  - 체크 끔 → PC Git `user.email` 사용
  - 공개/비공개는 “누가 보느냐”만 바꿈 (주소 자체를 만들지 않음)
  - 구현: `hide_real_email` → `resolve_commit_identity` / `preview_commit_email`
- 상세: `docs/PII_CROSS_VERIFY.md`

## 키보드 단축키 — F11 전체화면

| 창 | 구현 위치 | 방식 |
|----|-----------|------|
| 메인 창 (만들고 올리기 / 받기 / 동기화 3탭) | `app/ui/main_window.py` `MainController._toggle_fullscreen` | 이미 최상위 `QMainWindow` → `showFullScreen()` / `showNormal()`만으로 전-후 geometry가 정확히 복원됨. Frameless 플래그 조작 불필요 |
| 커밋 내역 팝업 | `app/ui/commit_history_dialog.py` | `QDialog`라서 `Qt.WindowType.Window` 강제 지정 + fullscreen 전환 시 `FramelessWindowHint` on/off 필요 (Windows에서 `showNormal()` 단독 시 창이 사라지거나 크기 0이 되는 문제 회피). 열리면 기본으로 전체화면 진입 |
| 첫 실행 안내 (온보딩) | `app/ui/onboarding_dialog.py` | 위와 동일한 이유로 Frameless 토글 방식. 열리면 기본으로 전체화면 진입 |

공통: 포커스가 어떤 자식 위젯에 있어도 F11이 먹도록 `keyPressEvent` 오버라이드 대신 `QShortcut(QKeySequence(Qt.Key.Key_F11), <window>, activated=...)`을 씁니다.

메인 창은 다이얼로그 두 개와 달리 **처음 열릴 때 자동으로 전체화면 진입하지 않습니다** — 일반 데스크톱 앱 기대와 다르면 오히려 방해가 되므로, F11을 눌러야만 토글됩니다. 안내 문구(`Esc 닫기 · F11 …`)도 다이얼로그의 인-윈도우 타이틀 바에만 있고 메인 창에는 넣지 않았습니다 — OS 타이틀 바만 있고 넣을 자리가 마땅치 않기 때문. (Orca computer-use의 `press-key`는 F11을 지원하지 않아 실제 사용자 입력 재현이 필요하면 PowerShell `SendKeys` 등으로 우회해서 검증했습니다.)
